盛隆原图 scp 失败排查

报错原文：Host key verification failed.

这不是登录私钥坏了，也不是图片没下下来。电脑已经连上测试机 10.180.34.16，但服务器这次出示的主机指纹，和本机 known_hosts 里记下的那条对不上。Agent 使用 BatchMode=yes，不能弹出「是否信任」让人点 yes，所以直接失败。本地下载的图片还在。

目标机器

  • 地址：cisdi@10.180.34.16，端口 22
  • 远程目录：/mnt/data01/embedded/projects/wangyutai/sl_feigang/test_images_full_car
  • 在本机用 PowerShell 执行下面的命令。先确认能访问公司内网。

1. 先确认是哪一把锁

ssh -v -o BatchMode=yes -o ConnectTimeout=15 cisdi@10.180.34.16 echo ok
倒数几行看到含义下一步
Host key verification failed 主机指纹不一致 做第 2、3 步
Permission denied (publickey) 主机指纹没问题，登录私钥或服务器授权丢了 跳到文末「登录私钥」
ok SSH 已经通 不用改配置，重新跑下载，或只补传已有日期目录

2. 对比旧指纹和新指纹

看本机以前信任过的记录：

ssh-keygen -F 10.180.34.16

有输出，说明这台电脑曾经连通过。再看服务器现在出示的指纹：

ssh-keyscan -t ed25519,rsa 10.180.34.16

两边算法相同、字符串不同，就是测试机的主机密钥换过了。常见原因：机器重装、sshd 重新生成密钥，或网络中间换成了另一台机器。

3. 确认机器身份后，接受新指纹

先问维护 10.180.34.16 的人：这仍是原来的推理测试机。确认后再执行。这次必须去掉 BatchMode，否则还是不会问你。

ssh-keygen -R 10.180.34.16
ssh cisdi@10.180.34.16

出现 Are you sure you want to continue connecting 时输入 yes 后回车。

再用和 Agent 相同的方式复测，必须看到 ok：

ssh -o BatchMode=yes cisdi@10.180.34.16 echo ok

4. 补传已经下好的图片

不用重新下载。把本地日期目录里的路径换成自己的实际路径。datasets 不用传，Agent 本来就会排除它。

scp -r -o BatchMode=yes "D:\盛隆图片\2026-09-22" cisdi@10.180.34.16:/mnt/data01/embedded/projects/wangyutai/sl_feigang/test_images_full_car/

这条成功后，再在 Agent 里重新下载也可以，scp 不应再报同一句错。

如果第 1 步是 Permission denied

主机指纹已经不是问题。登录私钥必须放在启动 Agent 的那个 Windows 用户的目录里。A 账号配的 key，用 B 账号开 Agent，读的是另一份 .ssh。

dir $env:USERPROFILE\.ssh
ssh -v -o BatchMode=yes cisdi@10.180.34.16 echo ok

详细日志里应出现 Offering public key，以及 id_ed25519 或 id_rsa。没有私钥文件时，把对应的 .pub 追加到测试机 cisdi 用户的 ~/.ssh/authorized_keys，不要只把私钥拷来拷去却没登记公钥。

为什么以前能用、最近不行

SSH 有两把锁。known_hosts 认的是服务器是不是原来那台；id_ed25519 认的是你是不是被允许登录的人。这次死在第一把锁。

以前能通，说明登录私钥多半还在。最近不行，几乎都是测试机主机密钥变了。Agent 禁止交互确认，旧指纹会一直挡住，直到有人在这台电脑上执行一次上面的 yes。
